# 技术设计与边界

## 模块

`core` 用纯 Kotlin 表达检测与状态转换；Android 服务负责获取节点和执行操作。`app` 将记录写入 Room，并通过原生 Android View 提供首页、周报、取证和设置。`demo` 与主应用属于不同包名，实际产生跨包窗口事件；模拟目的页在主应用的专用 Activity 中，其窗口被映射为明确的演示目标。

## 一次会话

1. 观察新的前台非系统包，用单调时钟 `elapsedRealtime()` 记录起点。它只是“前台进入”，不是准确的进程冷启动判定。
2. 在前 10 秒内扫描前台应用的所有应用窗口，每个窗口最多 500 个可见节点。事件扫描间隔至少 100ms，限流事件保证补扫，连续事件不推迟排队中的扫描；静态页面前 2 秒每 150ms 检查，随后每 350ms 检查。开始点击后停止轮询；新会话取消旧任务。
3. 唯一、可点击、大小合理、角落中的明确跳过标签，才允许节点点击。文字本身不可点时，可通过同样满足检查的小容器点击。无障碍点击被拒绝、或点击 200ms 后控件仍在时，重新采集节点并验证唯一性、位置未变、顶层等条件，最多触摸一次。页面切换、设置关闭或新的用户操作会阻止兜底。报告记录识别时点、首次操作时点及耗时；这些不是广告加载耗时。
4. 对不可点击的唯一右上角小尺寸跳过文字，要求同时读取明确广告标记、文字启用，并在新节点中核对同位置、顶层后触摸中心。只扩展文字区域的最小高度到 8dp，其位置及最大尺寸更严格，不操作全屏广告父层。
   无可用节点时，可选 OCR。每次会话最多 3 轮、开始间隔至少 0.9 秒，每轮最多两张独立截图；两张画面均要求明确广告标记（含 AM广告）与唯一角落跳过文字，中心偏移不超过 6dp 且交叠比例至少 60%。截图间隔至少 450ms，整轮最多 2.5 秒，第二帧从截图请求到决策最多 700ms。纯内容动画不取消；窗口切换、新交互、包名/尺寸/密度变化、设置关闭、白名单或过期时丢弃。回调按会话与任务编号隔离，一次只接受一轮识别结果；超时任务的迟到结果不执行操作。
5. 从首次识别广告起 6 秒内，目标属于有限名单、双方不在白名单、未确认跳过成功时可请求返回。单纯发起过点击不再关闭返回保护。默认开启误触保护，允许广告仍在时的点击触发返回；识别前、普通页面的点击仍放行。关闭误触保护后，所有观察到的用户点击均放行。
6. 最多一次返回键；700ms 后仍在同一目标应用且未观察到新的用户操作时，最多尝试通过 launcher Intent 打开原应用一次，可能进入首页。新交互、其他前台应用、关闭守护、白名单变更取消后续操作。通过窗口事件与前台节点复查，在 3.4 秒内确认原应用恢复才记“确认返回”；否则只记提示，不连续返回。旧回调通过会话编号和请求对象身份隔离。
7. 主界面、启动器、权限/安装/电话等系统界面会重置上下文；同包内容变化不会延长窗口。

## 不确定性

无障碍不是意图识别接口，无法百分百判断主动跳转或真实广告来源；一些 App 不发出点击事件。误触保护会同时撤回用户有意点击的开屏广告，可在设置中关闭；普通页面与白名单仍放行。目标名单只是有限启发式，浏览器和商城也可能用于正常任务。源窗口的广告识别是必要条件，但不是法律或业务层面的证明。

按钮由不可访问的画布绘制、识别器无法读取、无法截图、非角落布局和多候选等情形保守放行。OCR 不绕过安全窗口。版本 0.1 不处理多窗口坐标变换、悬浮窗复杂遮挡或覆盖全部厂商桌面。

## 数据与权限

- 不申请 `INTERNET` 或 `ACCESS_NETWORK_STATE`；删除平台上传客户端和明文网络配置，ML Kit 的 CCT 上报后端继续移除。邮件由用户自己的邮件应用负责发送。
- 默认不启用服务逻辑、截图或 OCR；它们分别有用途说明。
- 屏幕节点仅用于当次识别，不写入数据库。事件仅记录时间、源/目标包、操作、简短观察、截图路径和估算时长。
- OCR 图片仅在内存中处理，任务完成后释放。
- 取证图片位于应用私有 `files/evidence`，报告位于私有 `cache/reports`。仅用户点击分享时通过 FileProvider 临时授权所选接收应用。
- 邮件草稿包含所选报告文字、包名与应用名、机型、系统和净启版本；截图逐条勾选才加入 ZIP。收件人预填 `MOMO20170611@outlook.com`，用户在邮件应用中发送。本机记录保留；不记录或宣称发送成功。详见 [邮件反馈](EMAIL.md)。
- Android 备份关闭。应用启动时及之后每 6 小时清除 30 天前的事件与文件；页面最多读 1000 条。删除数据时暂停守护并使在途取证写入失效。
- 语音仅选择设备安装的离线中文声音；不自动下载、不向网络 TTS 发送文本。

## 报告

原始截图保留，标注副本另存。ZIP 内附观察文本与两份图片的 SHA-256。哈希仅用于比对完整性，没有可信时间戳或来源认证能力。图片可能在事件之后采集，不能保证截到跳转发生的瞬间。

“倒计时偏长”“控件偏小”“未发现可读跳过控件”均标为观察，不把 dp 当毫米，不将“未读取到”表述为“确实没有”，不自动认定违规。应用不提供举报入口；报告用于用户自行核实，或由用户通过邮件反馈识别问题。

## 后续优先事项

1. 根据真机失败案例补充具体包名/版本规则，并增加相应回归样本。
2. 对点击前后的页面变化进行确认，进一步区分请求和实际跳过成功。
3. 测量后台保活、OCR 延迟、误点击与误返回，开展无障碍体验测试。
4. 如新增社区规则导入，加入 schema 校验、版本范围、签名验证与撤销机制，禁止直接信任远端坐标。
5. 远程家庭周报需要单独设计账户、同意、端到端隐私边界；本版本没有云同步。
