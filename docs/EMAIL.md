# 通过邮件反馈报告

反馈邮箱：**MOMO20170611@outlook.com**。

## 发一条报告

1. 打开净启 → **取证** → **查看报告**。
2. 点击 **通过邮件发送报告**。
3. 确认收件邮箱；如需提供截图，勾选“附带截图”。默认仅包含文字。
4. 点击 **打开邮件应用**，选择已安装并登录的邮件客户端。
5. 检查预填的收件人、正文和 ZIP 附件，可以补充问题描述，再由本人点击 **发送**。

## 发多条报告

取证页 → **选择报告通过邮件发送** → 勾选记录 → **通过邮件发送所选报告**。下一步可逐条决定是否带截图，所选报告会合并为一个 ZIP；不会带上未勾选的报告。

ZIP 内有 `feedback.txt` 和每条报告的独立目录，选中的截图另附 SHA-256 校验值。正文包括所选事件、应用包名、净启版本、手机型号与 Android 版本，方便排查。演示记录继续明确标为演示。

## 设置页

**设置 → 报告反馈** 显示邮箱，可以复制邮箱，也可直接进入报告选择。无需填写平台地址、上传码或收件邮箱的密码。

## 没有邮件应用 / 没有带上附件

净启不保存邮箱密码，也不在后台自动发信。手机需安装并登录可发送邮件的客户端。若无法打开邮件应用，会提示复制邮箱与报告文字、或导出 ZIP 后自行添加为附件。

不同客户端对附件的支持可能不同。若邮件编辑页没有显示 ZIP，请返回报告页使用“导出报告与截图 ZIP”，然后在邮件里手动添加。最终发送和投递状态请查看邮件客户端的已发送/发件箱；净启不会把打开编辑页显示成“已发送”。

附件最大 15 MB；如果提示过大，可少选几条报告或取消部分截图后重试。为了避免改写已经交给邮件客户端的附件，每次准备邮件都生成独立文件。

## 升级

安装新的 `JingQi-debug.apk` 覆盖同签名旧版即可，无需先卸载。0.3.0 移除了旧“开发者平台”页面和上传入口，首次打开会清理旧平台地址与上传码，守护设置、白名单和本地报告保留。后台历史数据不受此操作影响。

净启恢复为不申请联网权限；报告只有在用户主动分享时交给所选应用。发送前检查截图中的个人信息。

实现参考：[Android 邮件 Intent 与附件](https://developer.android.com/guide/components/intents-common#Email)；附件通过 FileProvider 授予临时读取权限。
