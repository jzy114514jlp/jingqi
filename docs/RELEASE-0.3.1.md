# 净启 0.3.1

本版处理两个反馈：百度网盘开屏跳过偏慢，以及误点广告后未返回。

提供的百度网盘 ZIP 只有一份 `report.txt`，记录了“跳过控件偏小”，没有截图、点击耗时或目标 App；因此不能据此确认具体广告 SDK 行为，也没有据此编造百度专用控件 ID 或坐标。

## 调整

- 原先页面事件在 180ms 限流内被忽略，最后一次界面变化可能只能等稀疏定时扫描。现在保证尾部扫描，连续事件不会推迟已排队的扫描；事件最短间隔 100ms。无事件时，前 2 秒间隔 150ms，后续间隔 350ms，最多观察 10 秒。
- 原先无障碍点击后固定等待 800ms 才考虑触摸。现在 200ms 后复查，且触摸前重新确认唯一、同位置、顶层、可操作的小角落按钮；用户其他操作或前台变化时取消。系统拒绝节点点击时可立即复查并触摸。
- 原先所有点击都会使自动返回放行。新增默认开启的“误触广告后返回”，允许已识别开屏广告中的点击触发返回。仍要求防自动跳转开启、首次识别后 6 秒内、已知目标、双方不在白名单。识别前点击和普通页面点击继续放行；想主动查看广告可关闭误触保护。
- “已尝试跳过”与“已确认控件消失”分开，失败的跳过尝试不会直接取消返回保护。
- 一次返回键未生效且同一目标仍在前台时，700ms 后最多尝试打开原应用一次，可能回到首页。出现新操作、其他应用或关闭守护时取消；前台根节点也可确认返回，不再完全依赖新的窗口事件。3.4 秒未确认则只记录提示。
- 报告增加识别时点、操作耗时、返回请求及未操作原因。邮件收件人仍为 MOMO20170611@outlook.com，开发者平台不恢复。
- 演示实验室更新为 0.2.0，新增场景 10；场景 03 改为普通页面主动跳转，验证正常操作继续放行。

## 手机复测

1. 将 `JingQi-0.3.1.apk` 覆盖安装到已有净启上，打开并确认守护正常；无需卸载。
2. 在设置里确认“防自动跳转”“误触广告后返回”均开启，百度网盘及跳转目标不在白名单。
3. 重新打开百度网盘，出现开屏广告后观察跳过。若仍慢，发送同一时段的“页面观察”“执行跳过”“操作提示”，新版包含更多时序信息。
4. 在出现已识别开屏广告时误点，观察是否回到百度网盘；也复测普通页面分享/支付等正常跳转，以及关闭误触保护后的广告跳转。
5. 安装新版演示 APK，运行场景 03、08、09、10；场景 10 进入约 1 秒后点击，分别验证误触保护开/关。

尚无已连接真机，不能声称百度网盘已达到某个关闭耗时或自动返回成功率。实际结果受广告布局、可访问节点、系统后台策略和任务栈影响。自动测试和构建结果见 `VERIFICATION.md`。
